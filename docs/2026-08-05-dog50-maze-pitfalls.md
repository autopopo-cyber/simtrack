## 一、核心设计原则（主人指令，不可违背）

| 原则 | 内容 |
|---|---|
| **碰撞=0** | 现实中不允许碰撞。不靠物理碰撞挡（slide直驱不可靠会穿墙），靠**运动学约束**：前瞻测距 + 制动约束 v≤sqrt(2·A_DECEL·d) + 加速度限制 + 预判转向 |
| **不作弊** | 真实地图未知，从头扫描。A* 必须用 SLAM grid，**禁止用世界真值规划**。UNKNOWN 可通行但代价高（traversable + UNKNOWN_PENALTY=8），执行层撞墙写回 WALL |
| **效率** | 50m 小地图不该走几十万步。参考成熟 frontier_exploration：门聚类/评分/换门/去噪 |

## 二、卡死三连环 bug（墙边场景）

1. **scan 墙前膨胀**：`gset(prev, WALL)` 把机器人脚下格标 WALL → find_gates 起点失败 → 空门。修复：墙前格标 FREE。
2. **find_gates 起点过严**：贴墙时 walkable=False → 空门 → 原地 bounce 死循环。修复：起点放宽 `gget!=WALL` + `_nearest_walkable` BFS 脱困。
3. **主循环 path=None 只 _bounce 不 step**：永不移动，stuck 检测不触发。修复：path=None 调 `mv.step(FINISH)`。

## 三、迷宫赛道结构（关键！）

50m 蛇形赛道**不是简单蛇形走廊，是迷宫**：
- 10 段水平走廊（y=2.5+5k），段间墙**有缺口**（y=15.0 缺口在 x<4.1）
- 连接段（x≈2.5/47.5）有横向段间墙，缺口窄（~10° 视角，如右侧 y=9.3-10.6 缺口在 x≈46）
- **`_bounce` 候选必须每 5° 扫 360° + 推进评分**——稀疏角度（±[10,20,35,...]°）漏掉窄缺口是卡死主因

## 四、探索效率 8 项改进（commit 1a03d58）

1. 门聚类质心 `cluster_gates()`：200 单格 → 4-10 region
2. `pick_gate` score 模式：`0.55·advance + 0.25·(1/dist) + 0.20·(size/50)`（终点导向）
3. `traversable()`：UNKNOWN 可通行 + UNKNOWN_PENALTY=8
4. 失败换门：A* 失败试下 3 个
5. `back_blacklist`：BACK 过没新门的路标跳过
6. 碰撞检测用真实几何 `is_obstacle_world`（0.7m）非 blocked()（0.9m 假阳性）
7. Mover 硬防穿墙 + 撞墙写回 WALL
8. `_bounce` 每 5° 扫 + 推进评分（`dot·2 + min(d,4)`）

## 六、提速实验（2026-08-05，4m/s）

主人问"最大速度提到4m/s有用吗"。实测结论：**有用但效果有限**（瓶颈在 bounce/探索不在直线速度）。

| seed | 2m/s 版 | 4m/s 版 | 变化 |
|---|---|---|---|
| 7 | ✅ 728s / 21.3万步 | ✅ 649s / 18.3万步 | -12% 时间，-14% 步数 |
| 170456 | ✅ 768s / 23.9万步 | ⏳ 700s 差3m | 接近持平（bounce 221→252） |

**关键组合改动**（commit 4c34c8b）：
1. SPEED_MAX 2→4, A_ACCEL 3→5, A_DECEL 5→8
2. **YAW_RATE 保持 1.5 不提高**——第一次试 2.5+4m/s 窄缺口过冲卡死（7万步卡连接段）
3. **近墙限速**：`d_clear < 2.0m 时 v_des ≤ 1.5`——开阔跑 4m/s，狭窄处自动减速防过冲

制动距离验证：v=4, A_DECEL=8 → v²/2a = 1.0m < LOOKAHEAD 4.0m ✅ 安全。

**教训：光提速度没用，必须配合"近墙限速"**——真实机器人行为：开阔提速、狭窄减速。

## 八、双层地图 + 射线清除（2026-08-05 10小时目标）

主人 10 小时目标：①探索效率 ②已知地图+障碍变化快速寻路（走中间）③随机位置绑架恢复。

### 性能元凶（重大发现）
- **EGL 离屏渲染 3.5 秒/帧**（llvmpipe 软件渲染，与分辨率无关）——视觉识别每 40 步渲染一帧会把导航从 14.9万步/s 拖到 ~10步/s！
- **解决**：视觉默认关闭（`--vision 1` 才开），标牌几何默认关闭（`--landmarks 1` 才开）
- 教训：**渲染类功能必须默认关**，否则拖死核心算法

### 双层地图（借鉴 ROS costmap 分层）
- `static_grid`：旧地图背景（只读），`KNOWN_MAP_MODE` 时规划叠加
- `gget_plan()`：规划视图 = static 墙永远 WALL + live 障碍/自由优先
- `scan()` 加**射线清除**：射线穿过格强制 FREE（旧障碍被"照"掉），命中格 WALL
- 解决"已知地图+障碍变化"：旧障碍位置新扫描自动清除，static 的墙不受影响

### 走中间 Voronoi 代价
- `VORONOI_C=2.0`：KNOWN_MAP_MODE 下 A* 代价 + C/d²（d=离墙格数）
- 贴墙爆炸、中线最低——路径自然贴通道中线

### 新参数
- `--save-map <npz>` 阶段1保存地图 / `--load-map <npz>` 阶段2加载
- `--random-start 1` 绑架随机起点（避开墙/障碍） / `--target start|finish`
- `--obs-reseed <step>` B阶段运行中障碍变化
- `--vision 1` / `--landmarks 1` 视觉/标牌（默认关）

### 标牌贴墙（主人"别堵路"）
- 标牌贴**段尾横墙内壁**（x=49/1 交替），机器人沿 x 正对可见
- 侧墙标牌不可见（相机朝前看不到 y 方向墙）——正前方横墙才可见

## 九、08-06 二维码标牌攻坚（hfield 世界修正）

主人方向：标准黑白二维码（DICT_7X7 四角明显）+ 图像金字塔多尺度 + 标牌放大 2 倍 + 贴墙 1m 高。

### 9.1 世界模型（最重要发现）
- hfield `size="25 25 4 2"` → 表面高度 = 2 + 4×(灰度/255)。**通道(128)=4.008m，墙(191)=4.996m**
- **机器狗 body 必须在 hfield 表面上方**（BOT_Z=HF_SURF+0.5）——否则相机 z=0.5 在地底下，**全黑**！多轮"标牌不渲染/全暗"的元凶
- 标牌必须贴 hfield 表面（z=HF_SURF+0.02），地面 z=0.02 被实体 hfield 埋住

### 9.2 相机 roll 修正
- `euler="0 -1.5708 0"` 朝前但 **right=+z（天空在水平方向）→ 画面 roll 90°**（地面在左、天空在右，主人截图发现）
- MuJoCo euler 是 **extrinsic xyz**（先 z 后 y 后 x 作用）——绕 y -90° 后要 up=+z 需加 z=-90°
- 修正：`euler="0 -1.5708 -1.5708"` → up=+z（天空上）、right=-y、fwd=+x ✅
- 验证法：红/黄/绿/蓝球放相机前后左右，看图像位置（绿球 -y 应在右侧）

### 9.3 plane 纹理旋转方向
- **绕 y 旋转（横墙）纹理可靠，绕 x 旋转（侧墙）纹理异常**——侧墙标牌所有距离/所有翻转方向都识别失败
- 结论：标牌只能贴横墙（法线 ±x）

### 9.4 ArUco 需要闭合背景
- 标牌在转弯口开口区（无墙背景）→ ArUco 边界分离失败
- 修复：标牌后面 0.6m 加**深色背景板**（2.6m box，比标牌大 0.3m/边）——像真实路牌
- **背景板方向 bug**：写反了挡在标牌前面 → 修正 side==1 背景在 +x

### 9.5 标牌尺寸与位置
- 1.5m 标牌在狗 2m 距离太大占满视野（ArUco 失败）；0.75m 配合金字塔 scale=0.5 稳定
- 主人指令放大 2 倍 → **2m×2m**（size 半尺寸 1.0）
- 标牌中心必须**通道中心线**（y=2.5+ch*5）——贴分界墙边缘会嵌进墙（码只显示一半）

### 9.6 金字塔级联粗筛（主人思路）
- 每帧 6 档金字塔全跑（无标牌 25ms 浪费）→ **0.25x Laplacian 能量 <200 跳过全部**
- 实测判别：无标牌 23-84，有标牌 231-1684，阈值 200 零重叠；粗筛 0.3ms
- 精识别用 INTER_LINEAR（INTER_AREA 缩小模糊小码致检测失败）

### 9.7 box 墙堵死 U 型弯（主人一眼看出）
- 现象：侧墙 x∈[0,50] 全程 + 横墙 x=0.25/49.75 → **所有 U 型弯堵死**
- 迷宫真实结构（实测 track_clean）：分界墙 y=5k，**转弯口交替开口**（y=5,15,25,35,45 右开口 x=50；y=10,20,30,40 左开口 x=0）
- 修复：分界墙只到开口前（奇数右墙 x∈[0,45.5]、偶数左墙 x∈[4.5,50]），删横墙
- **教训：加几何前先验证地图真实结构**（先跑连通性/看墙段，再改场景）

## 十、08-06 探索效率三个根因修复

主人问性能后死磕，找到 3 个根因（systematic-debugging）：

### 10.1 find_gates 0 门 bug
- 现象：狗反复 bounce 卡死，gates=0
- 根因：`cluster_gates(gates, min_size=8)`——探索早期前沿窄（门格 3-5 个 <8）→ **全被过滤 → 0 门**
- 独立复现：3 门格 → []，5 门格 → []，12 门格 → 正常
- 修复：min_size 动态化（min(8, max(2, len//2))）+ 全过滤时保底返回最近门

### 10.2 薄斜墙漏扫（最大发现）
- 现象：狗在 (48.5,2.2) 被挡，wall=False obs=False 但 d_clear=0.35
- 排查：track_clean 有 **45° 薄斜墙**（0.1m 厚）——bounce 点前方 0.35m 正好撞上
- 根因链：LIDAR_RAYS=120（3°）→ 15m 处射线间距 0.78m > 墙厚 → 漏扫 → 斜墙格=UNKNOWN → A* 认为可走 → 执行层 blocked 撞墙
- 修复：LIDAR_RAYS 120→360（1°）；LIDAR_TICK 20→10（减少两次 scan 间盲区）
- 效果：coverage 13%→31%（2.4×），狗从卡通道 0 推进到通道 2

### 10.3 ASTAR_MAX_EXPAND 不足
- 现象：KNOWN_MAP_MODE 每步 bounce 原地不动
- 根因：蛇形迷宫全程 A* 需扩展 >3 万格（BFS 全图 23.5 万格），ASTAR_MAX_EXPAND=30000 不够 → astar_to 返回 None
- 修复：30000→250000 → A* 成功规划 451m 全程（522 格）

## 十三、08-07 里程碑：HPA* + yaw bug 修复（终极三坑）

### 13.1 全程 A* 50.8s — 移植 HPA* 分层寻路
- 现象：KNOWN_MAP 全程规划 50.8s（缓存空），分段 A* 每段仍 430-560ms 超 100ms 铁律
- 根因：全程 A* 需扩展数万格，wall_dist 每格扫 441 次 × 25 万格 = 1.1 亿查询
- 修复：移植 ROS 标准 HPA*（`scripts/hpa_star.py`）——CELL=50 格(5m)、216 门、cell 内 BFS 配对，粗层门网络+细层短 A*。**全程规划 0.38ms**（13 万倍）
- 教训：主人方法论"先移植成熟算法，不自研死磕"——ros 就在那放着

### 13.2 距离场 BFS 取 min bug — 贴墙路径根源
- 现象：HPA 反向路径贴墙走 x=45.05（物理墙 44.975），狗 bounce 卡死 (45.2,34.9)
- 根因：`di[j] = n if n < v else (w if w < v else v)`——**n 优先，忽略更小的 w**。墙多时 n 已传播（50），左邻是墙（1），错误取 50 → 距离场以为开阔 → 路径贴墙
- 独立测试墙稀疏时 n=INF+1>v 走 w 分支碰巧正确——单测过了不代表真地图对
- 修复：`if w < n and w < v: di[j] = w`（取三值最小）→ dist[450]=1（正确）→ 路径走开口中间
- 教训：BFS 传播必须取 min(v,n,w)，不能"n 优先"

### 13.3 yaw 控制被物理读回覆盖 — 终极根因 🎯
- 现象：绑架恢复 seed42 finish 150s 卡死 bounce 120+，狗直线冲出通道往 x=48 跑；DBG 显示 yaw 恒 0° 不转
- 根因：`self.d.qvel[2]=0; mujoco.mj_step(...); self.yaw = self.d.qpos[2]`——**每步转向 dyaw 后被物理 qpos[2]（恒 0）重置**。狗从未真正转向，永远朝初始方向直冲
- 为什么之前 KNOWN_MAP 能跑通：起点 (2.5,2.5) yaw=0 恰好朝路径方向，靠 bounce+限速硬走完（bounce 94）
- 修复：yaw 是控制变量，**直接写回物理不读回**（`d.qpos[2]=self.yaw`；滑动模型 friction=0 mj_step 保持）
- 效果：bounce 94→0，KNOWN_MAP 241s→125s，探索 242s→127s，绑架 4/4 全到达
- 教训：**控制变量和物理状态分离时，读回方向要三思**——`self.yaw = d.qpos[2]` 这种"同步"会吃掉所有控制量

### 13.4 大转向限速（DWA 思想）
- 现象：修复 yaw 后仍需防直冲——随机起点 yaw=0 但目标在背后 170°，转向慢会先冲一段
- 修复：`abs(err)>1.0 rad` 时限速 1.0m/s，先转身再加速（曲率越大速度越低）
- 效果：配合 yaw 修复，bounce 全 0

### 13.5 任意通道目标 --target ch<N>
- 现象：--target 只支持 start|finish，无法导航到任意通道二维码
- 修复：解析 landmark_positions()（每通道 1 标牌），`--target ch4` → 目标 (45.8,22.5)
- 验证：ch0-9 全通道 100% 到达 bounce 0

### 13.6 ARRIVE 判定 3.0 → 3.5m
- 现象：ch0 目标 (45.8,2.5) 狗停在 (46.0,5.5)，距离 3.007m 差 7mm 判不到
- 根因：二维码在通道尽头转弯口前，3.0m 在斜墙边会差一点
- 修复：3.5m（够近即可）
