# firefly 原始版 vs 当前版对比 + 终点发现机制设计

> 日期：2026-08-09
> 背景：主人质疑"走歪了/钻空子" + 建议"终点发现：每个门后都可能是潜在终点"
> 状态：分析完成，设计待主人审查

## 一、对比结论（firefly 原始版 583dedd vs 当前 e0d0d0c）

### ✅ 探索算法核心 = 与原始完全一致（没走歪）

| 组件 | 原始 firefly | 当前 | 结论 |
|---|---|---|---|
| find_gates 门定义 | FREE 邻接 UNKNOWN + wall_dist>1 + bad_gates 黑名单 | 同 + (cx,cy)!=(vx,vy) 排除起点自身 | 一致（起点排除是自旋 bug 修复）|
| pick_gate 评分 | 0.55·advance + 0.25·1/d + 0.20·size | 同 | 一致 |
| 主循环决策 | bounce>8 拉黑换门 / 失败换门 / no_gate→BACK | 同 | 一致 |
| MAX_GATE_DIST | 3000（全图） | 500（全图，地图 500 格） | 等效 |
| cluster_gates 聚类 | 门格 BFS 聚 region | 同 | 一致 |

**结论：探索算法本身没走歪。**"找门和前线"的语义就是 find_gates 的实现——门 = 未知前沿（已知/未知边界），不是"墙上的洞"。debug 中"缺口"的说法是我的口语，容易误导，实际代码语义没变。

### ✅ 无特权化改动 = 主人 08-08 明确要求（方向正确）

- 雷达 360°→180°（原始全向=特权）
- blocked 去 is_obstacle_world（原始用真值=特权）→ 纯感知 gget_plan==WALL
- save_map 去 sample_hf 真值 → 感知版
- known-raw 默认关
- 禁入区 0.05m（主人新要求"狗只在路中间"）

### ⚠️ 可疑补丁（为绕无特权化卡死加的，主人怀疑对）

1. **ROBOT_DIA 4→6**（hpa_star.py）——改 HPA 膨胀对齐 STOP_MARGIN 0.55m——**钻空子嫌疑最大**：改全局膨胀适应执行层参数，影响 M3 已知地图行为
2. **GATE-STALL 无进展黑名单**（主循环新增）——同一 gate 选中但距离不降 → 黑名单——**独立于原始 bounce 机制的补充**——原始没有
3. **EXPLORE-DONE 自动切换**——探索完自动切 KNOWN_MAP——**原始是手动 save_map/load_map 两阶段**——自动切是新增
4. **_nearest_walkable min_dist 参数**——HPA 起点放宽找 dist≥4 格——补丁性质
5. **HPA 起点放宽 + astar_to fallback**——贴墙时 HPA 规划失败兜底——补丁性质
6. **开机自旋**——初始扫描转一圈——**合理性较高**（真实机器人上电自检旋转），但原始没有

### 🎯 关键真相

**原始 firefly 探索代码从没被真实跑过**——M2/M3 里程碑全部 known-raw=1（真值地图 KNOWN_MAP 模式）。探索模式（无特权）首次真实运行暴露卡死（左端斜边窄缝/贴墙巡航/穿未知撞墙）——**这是无特权化的新挑战，不是走歪**。但补丁像"打地鼠"，需要系统性审视。

## 二、终点发现机制设计（主人建议）

### 核心思想

> "每个门后都可能是潜在终点。这是走迷宫的方式，答案隐藏在未知后。"

**现状**：探索把所有未知扫完才导航到终点（蛇形赛道被迫穿完 10 通道）。
**改进**：每个门（未知前沿）都可能是通往终点的门——到门前先探测门后，是终点就直接冲。

### 设计

**门后终点探测**（find_gates 后，对每个 gate 计算"终点潜力"）：

```
对每个 gate (gx, gy)：
    1. 方向 = gate 的 UNKNOWN 邻域质心方向（未知在哪边，门就通往哪边）
    2. 从 gate 向 UNKNOWN 方向 BFS（限 10 格 = 1m 深）
    3. 探测内容：
       a. 是否邻接地图边界（x<0/x>50/y<0/y>50）→ 出口候选
       b. 是否邻接 FINISH 区域（终点 (2.5,47.5) ±1m）→ 终点候选
       c. 门后 UNKNOWN 是否大片开阔（>50 格）→ 新区域候选（非死胡同）
    4. 终点潜力 score_add = 命中 (a)/(b) → +0.5；命中 (c) → +0.1
```

**pick_gate 改动**：score = 原始评分 + 终点潜力（终点门优先选）。

**执行层**：选中终点门后，正常 fine_path 走过去；到门前 scan 穿透（雷达射入缺口），确认门后是出口/终点 → 直接穿越。

### 对蛇形赛道的效果

- ch9 末端 (2.5,47.5) 邻接地图顶边 y=50 → 终点特征 (a)
- 每个分界墙缺口后是新通道（非终点）→ 无终点特征 → 正常探索
- 效果：**最后一个门（ch8→ch9 缺口）终点潜力高 → 优先穿越 → 直达终点**
- 次要效果：死胡同门（墙后）终点潜力低 → 延后探索

### 通用性

不依赖蛇形赛道：任何"门后邻接地图边界/终点标记"的场景都能触发——真实建筑中出口/楼梯间同理。
