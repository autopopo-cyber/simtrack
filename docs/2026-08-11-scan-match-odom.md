# 激光扫描匹配定位(去真值位姿依赖)设计 —— 2026-08-11

> 主人指令(2026-08-11):真机器狗无法准确知道自己的速度和位移,只有估算;
> 唯一比较准的是激光雷达(厘米级),其他都不准,尤其需要积分的瞬时速度和位移。
> 调研 ROS 怎么实现,修改算法。先从无障碍赛道开始;如果走廊太长影响定位,
> 每 15±5m 加一个随机位置固定障碍辅助定位。
> 前置审计:代码程序审核-2026-08-11.txt(幻觉检查第 1/2 条:默认定位用真值、
> --odom 1 2% 噪声实测彻底失败)。

## 一、ROS 调研:里程计漂移 + 激光准,ROS 怎么做

| 组件 | 做法 | 对本项目的启示 |
|---|---|---|
| robot_localization (EKF/UKF) | 里程计+IMU 卡尔曼融合 | 只平滑不消漂——没有绝对参考,积分误差照样累积。单靠它不够 |
| AMCL | 粒子滤波定位:预测=里程计运动模型;**更新=激光 likelihood_field**——每个粒子位姿把当前扫描投到地图上,按命中点到最近墙的距离场打分(exp(-d²/2σ²)),好位姿权重高;KLD 自适应粒子数;map→odom 变换吸收全部修正,odom 系保持连续 | 核心思想可直接搬:**用距离场给"位姿假设"打分** |
| Cartographer | 局部 SLAM:**scan-to-submap 匹配**(分支定界多分辨率网格搜索,旋转+平移),把每帧激光对齐进子图,局部漂移厘米级;全局:位姿图+回环约束消累积漂移 | 网格搜索(而非粒子)更确定性、可复现,适合本项目;多分辨率防局部极小 |
| gmapping | 每粒子背一张图的在线 SLAM | 太重,不采用 |
| nav 架构 | odom 系(连续、漂移)→ map 系(准确、可跳变),amcl 发 map→odom | 修正加在估计位姿上,控制层每步读最新估计,等价 |
| 退化场景 | 长直走廊:沿走廊方向平移不可观测(对称性),粒子沿走廊拉成一条;靠回环/门/柱子破解 | 走廊 x 向修正天然弱 → **主人提的锚点障碍正是标准解法**(真实楼宇里的柱子/家具就是天然锚点) |

**结论:在"估计位姿"上做扫描匹配修正——把当前激光命中点投到已建栅格上,
网格搜索 (dx, dy, dyaw) 最大化命中点与墙的距离场似然,把偏移按权重拉回里程计。
这就是 AMCL likelihood_field + Cartographer 网格搜索的简化确定性版本。**

## 二、现状与根因(审计实测)

- `--odom 1`(默认 2% 速度噪声):决策/建图全用估计位姿,但**没有任何机制吸收
  位姿误差**——硬栅格地图把同一面墙在不同漂移处重复标记(双墙/走廊变窄),
  blocked 判的是估计坐标下的地图,真值位置穿墙出界(实测 12 万步碰撞、跑出
  y=53.6、不到达)。ArUco 修正只在看到标牌时生效(距离门控 5-25m、需正对),
  漂到几米后连标牌观测都救不回来。
- 0.5% 噪声能到达但仍有 127 步碰撞(一次墙根遭遇),违反碰撞=0 铁律。
- 根因:**缺一个持续、高频、不依赖外部设施的激光绝对修正源**。

## 三、设计

### 3.1 新增模块 `simtrack/scan_match.py` —— ScanMatcher

**似然场打分(AMCL likelihood_field)**:
- 地图 = PG(static+live 叠加视图)的 WALL 格;`cv2.distanceTransform` 得
  精确欧氏距离场 LF(米)。命中点似然 `exp(-d²/(2σ²))`,σ=0.15m
  (激光厘米级 + 栅格 0.1m 量化,误差预算主要给残余位姿差)。
- 总分 = 命中点似然均值 ∈[0,1]。

**命中点来源**:scan() 内部保存本次扫描的真命中(射线首中点,机器人系:
相对方位 + 距离),排除出界终止点;每 3 根射线抽 1 根(~120 点)。
机器人系存法与位姿无关——匹配时才用候选位姿变换到世界系,
因此同一份命中可以对任意位姿假设复用(AMCL 同理)。

**网格搜索(两档粗到细,Cartographer 多分辨率思想)**:
- L1:dx,dy∈[-1.2,1.2] 步长 0.15,dyaw∈[-6°,6°] 步长 1.5° → 17×17×9=2601 候选
- L2:L1 最优邻域 ±0.15/±1.5° 内步长 0.05/0.375° → ~7×7×9=441 候选
- 每档全向量(numpy):候选×命中 一次算完。120 点 ×3000 候选 ≈ 36 万次
  指数查表 ~5ms/档,每次匹配 <15ms,每 1s 一次 → 开销可忽略。

**采纳门槛(防坏匹配带偏,AMCL 的"低似然不更新")**:
- `score_best ≥ 0.35` 且 `score_best ≥ score_identity + 0.02`
  (结构不足以支撑修正时不动——宁可慢慢漂,不接受错修);
- 单次修正限幅 |dx|,|dy| ≤ 0.4m、|dyaw| ≤ 2°,指数加权 w=0.6 拉回
  (与 ArUco 修正同款平滑,防跳变);
- 只信墙命中:障碍命中格不进匹配(移动障碍不在图里/锚点障碍在图里,
  统一按"PG 里是 WALL 才算数"处理,天然兼容)。

### 3.2 接入 algo3_headless.py(--scan-match 1)

- 主循环每次 scan 前:`matcher.ensure(PG)`(重建 LF,≤1 次/匹配周期);
- scan() 末尾:命中存 `_last_hits`(机器人系);
- scan 后:匹配 → `odom.correct_pose(dx, dy, dyaw, w)`(Odometry 扩展
  yaw 修正),并同步 `mv.pose`;本 tick 决策即用修正后位姿。
- **写图时序**:scan 用修正前位姿写(本次命中不进自己的似然场——
  ensure 在 scan 前取快照),下一帧起写图用修正后位姿 → 漂移被限制在
  一个匹配周期(0.2s×4m/s=0.8m)以内,双墙/走廊变窄问题根除。
- 与 ArUco 修正共存:两者都是绝对观测,ArUco 频率低但全局,扫描匹配
  频率高但相对已建图——叠加不冲突。
- 默认关(--scan-match 0):不影响既有四场景回归(确定性不变)。

### 3.3 锚点障碍(--obs-anchors 1,主人方案)

走廊 40m 直道 x 向对称 → 扫描匹配对 x 不可观测(ROS 已知退化)。
每走廊沿中心线每 15±5m(=uniform(10,20) 间隔)放 1 个固定圆柱障碍:
- x 从 8+uniform(-2,2) 起步,累加间距至 x>42 止(每走廊 2-3 个);
- 横向偏移 ±0.5m(保两侧走线 ≥1.5m——PASS_CLEAR 不封、执行层不挤缝,
  吸取混合场"1.0-1.6m 边界缝探测成本"教训);
- 固定障碍:走既有 OBS_SEEN/安全圈机制,无移动豁免问题;
  它们是**永久墙格 = 稳定地标**,打破走廊平移对称,x 向可观测。
- 与 --obs-straight 等互斥(锚点是独立场景开关)。
