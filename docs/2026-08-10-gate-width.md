# 门宽度判断（2026-08-10 主人指令）——窄缝/栅栏陷阱识别

> 主人指令：①要不要做门宽度判断？现实中有很多窄的缝隙，能透过激光，但过不去。
> 如果算法能有效识别这类问题，也就不怕窄缝、栅栏陷阱了。
> ②算法要贴近现实情景：各种障碍、墙，**边缘精确点好**；如果这会带来问题，
> **想办法解决问题**（而不是靠模糊地图回避）。

## 一、根因诊断：为什么狗会被吸进窄缝

读码定位（test_scripts/algo3_headless.py）：

- **规划层零净空**：探索 A*（`jump_steps`/`find_gates` BFS）的通行判定 `traversable()`
  只看 `!= WALL`——**不量离墙多远**。门过滤只有 `wall_dist > ROBOT_R`(0.2m)。
- **执行层有边距**：DWA 障碍排斥 r+0.3、墙 keepout 0.05、STOP_MARGIN 0.4 制动。
- **错配 = 陷阱**：规划器把路径/门穿过 0.5~1.0m 窄缝（障碍↔墙），执行层物理上进不去
  → STOP → bounce → 确定性 A* 重规划又选同一条缝 → bounce 风暴，靠黑名单机械慢慢爬出。
- **澄清 08-09 的 A/B 失败**：那次实验（门过滤 wd>1 + 前沿 3×3）是把门质量门槛**往下放**，
  更多窄缝门被放进来 → bounce 93→1830。方向反了。门宽度判断是**往上提**：
  窄缝被显式识别为"过不去"，直接封闭，根本不成为门。

## 二、设计：地图精确 + 通行性判断在规划层（ROS costmap 分层思想）

| 层 | 内容 | 本项目对应 |
|---|---|---|
| 占据栅格（精确） | 墙/障碍是什么形状就建什么形状，不膨胀 | PG/G：KEEP_M=0.05 不动，射线 DDA 精确标记 |
| 通行性（规划层） | 距障碍 <机器人半径+余量 的格不可规划 | **PASS 净空场**（本里程碑新增） |
| 执行层 | 实时避障、制动 | DWA + keepout + v_brake（不动） |

ROS 对照：obstacle layer（精确占据）+ inflation layer（inscribed radius 膨胀）≈ PG + PASS；
frontier_exploration 的门 size/通行性过滤 ≈ find_gates 的 clear_ok 验收。
差异：PASS 对 UNKNOWN **乐观**（只对已知墙量净空）——探索语义必须允许走向未知，
ROS costmap 的 unknown 处理是配置项（lethal/free），我们显式选 free。

### 实现（algo3_headless.py，单文件改动）

- **PASS 净空场**：`DIST = cv2.distanceTransform(非墙)` 精确欧氏距离场（500×500 ~2ms），
  `PASS = DIST ≥ PASS_CLEAR`。PG 变更置脏、规划器首次用时重建（懒加载，不为每次 scan 付账）。
- **PASS_CLEAR = 0.6m**：= 狗半径 0.2 + 执行余量 0.4，对齐 HPA 细层 ROBOT_DIA=6 既有标准
  （已知地图模式 bounce 0 实测验证过的数）。**通行宽 <2×0.6=1.2m 的缝没有可规划中线 → 自动封闭。**
- 接入点（全是规划层，执行层/地图层零改动）：
  ①`jump_steps` 逐格 plan_clear（A* 不穿缝）②`find_gates` 内联走查低净空断路 +
  两处门验收 `clear_ok`（窄缝门拒绝并计数 `_NARROW_REJ`，[GATE] 日志可见）
  ③`_nearest_walkable` 两遍搜索：PASS 优先，traversable 兜底（狗被瞬态障碍标记围进
  低净空区时保证能起步，防起步死锁）
- **A/B 开关**：`--pass-clear 0` 关闭（回退旧行为），默认 0.6。
- **顺手修复**：`_nearest_walkable` 的 min_dist 判定改用 DIST 精确场
  （旧 wall_dist 只有 5×5 窗口，≥3 格的验证实际靠截断值 21 蒙混——HPA 起点吸附的潜在 bug）。

### A/B：PASS_CLEAR 0.3m 实测否决（主人质疑"0.6m 是不是给多了"）

主人身材账：狗 0.4m 宽 + 两侧各 10cm 防撞 = 0.6m 总宽 → 0.3m/侧 应该够？
实测（`--pass-clear 0.3`，四场景，全部到达但全面变差）：

| 场景 | 0.6m（采用） | 0.3m |
|---|---|---|
| 纯墙 | 123.4s / bounce 2 / coll 0 | 199.3s / **118** / 0 |
| 移动×4 | 135.3s / 0 / 0 | 154.0s / 10 / 0 |
| 固定×20 | 153.0s / 3 / 0 | 180.8s / 33 / 0 |
| 混合 | 152.4s / 1 / **0** | 196.6s / 16 / **621** |

0.3m 是**物理裸需求**，但规划净空要吸收的是误差不是碰撞：
①感知误差——0.1m 栅格量化、掠射噪声、障碍弧心偏移（可见面弧簇心偏近狗侧 ~0.3m）；
②控制误差——DWA 快路径采样点距 0.2m 不插值、4m/s 横向跟踪误差 0.1-0.2m；
③遭遇战闭环时间（移动障碍场特有）——相对闭合速度最高 4+1=5m/s，
决策周期 50ms + 制动距离（4m/s @ 8m/s² ≈ 1m）决定了狗不能把自己规划进
"障碍一靠近就无处可退"的窄空间。0.3m 净空留给体侧仅 10cm，
一格感知误差/一次近距遭遇就变现成擦碰（混合场 621 次碰撞多发生在移动障碍遭遇战）。
最有说服力的对照：纯墙场**没有窄缝**，0.3m 也 bounce 2→118
——代价不在"缝"，在"贴墙行驶"本身。10cm 防撞保留在物理碰撞边界（DWA r+0.3），
规划层 0.6m 让狗实际永远用不到它。

## 四、回归暴露的预埋 bug：跳步粒度奇偶（直奔瘫痪）——已修复

首轮四场景回归：移动×4（183.6s bounce 0）、固定×20（194.1s bounce 3）大幅改善，
但**纯墙/混合两场超时未到达**——狗都已看到终点（三角收敛误差 0.02m）、物理走到
距球 0.17m，却卡在"0 门 → BACK → A* 风暴"（301 次全程 A*，速率 163→37 步/s）直到超时。

根因（读码+日志定位，**预埋 bug，非净空场引入**）：

- `jump_steps` 开放区跳步恒取上限（2m/格点化），目标格不在跳步格点上**永远落不上去**
  → `astar_to` 必须精确落到 `(tfx,tfy)` 才返回路径 → 直奔 beeline 每次扩满 25 万格
  返回 None。终点在 4.9m 开阔通道里（跳步全 2m），目标格可达性 = 起点奇偶运气（~1/20²）。
- 基线能到达纯属侥幸：基线靠"门还没探完"持续到视觉到达窗口（200 步）内走近触发；
  净空场让狗的路径/时机略有变化 → 门先探完 → 直奔兜底暴露 → 风暴。
  **正是主人说的"精确化带来问题 → 正面解决问题"**：问题就是粒度奇偶，修它。
- 修复（`jump_steps` 目标对齐吸附）：走查跨过目标行/列时收步落在目标坐标上——
  先落目标行/列、再沿行/列精确落到目标格。对所有 astar_to 调用生效
  （终点直奔 / BACK 回路标 / HPA 兜底全受益）。

## 五、结论

- 窄缝/栅栏陷阱**可识别**：1.0m 缝（能透激光）在规划层整体封闭，狗从规划上就不被吸引；
  同时 1.95m+ 的宽路零影响——"明明有宽路却挤缝"的现象在规划层根除。
- 主人"边缘精确"的诉求成立：地图层没加任何膨胀（KEEP_M=0.05 原样），
  收窄问题靠规划层净空场解决——这正是 ROS costmap 分层的标准做法。
- bounce 全面消失（混合 69→1、移动 50→0、固定 37→3、纯墙 15→2）且混合场擦碰 24→0：
  之前相当比例的 bounce/碰撞就是窄缝/贴墙路径反复尝试的产物。
- 物理时间全面逼近极限：纯墙 123.4s（理论极限 ~120s），最重的混合场 152.4s——
  都在主人 2-5 分钟目标内（且富余一倍）。
- 精确化暴露的预埋 bug（跳步粒度奇偶）已根修——直奔不再依赖"门没探完"的运气。

## 六、后续方向：如何把穿缝阈值继续压小（主人 2026-08-10 追问）

0.6m 净空里只有 0.2m 是狗的身体，其余 0.4m 是**误差余量**。想让狗安全穿过更窄的缝，
正确路径不是硬降净空（0.3m A/B 已实测否决），而是**把误差本身做小**——
误差余量缩小多少，净空就能让出多少。按收益排序：

1. **移动障碍速度外推进地图层**（针对混合场 621 碰撞的主因：遭遇战闭环时间）。
   现状：DWA 层已有 0.5s 运动预测（`pred_t`），但**地图层的障碍标记没有外推**——
   雷达画的是"扫描时刻的位置"。可做：给 OBS_SEEN 障碍格簇估计速度（连续帧簇心差分），
   规划时按"位置 + 速度×前瞻时间"判定通行性，等效于把遭遇战闭环时间从误差预算里去掉。
   预期收益：移动障碍场景的净空需求 ↓0.2-0.3m。
2. **栅格分辨率 0.1m → 0.05m**（针对量化误差）。
   量化误差减半（±0.05m → ±0.025m/格）；窄缝宽度测量精度直接翻倍。
   成本：栅格 4 倍（500²→1000²），cv2 EDT ~2ms→~8ms 仍可懒重建；
   scan 向量化已是 numpy，主要成本在内存带宽——需要 profiling 确认不掉帧。
3. **控制误差收敛**：DWA 快路径采样点补子步长插值（点距 0.2m→0.05m，堵"跳过窄通道边缘"
   的漏洞）+ **窄道自动限速显式化**（路径点净空 <阈值 时 v_max 降档——低速下横向
   跟踪误差和制动距离都随 v 缩小，等于用速度换余量，扫地机器人过窄缝的标准做法）。
4. **掠射噪声收尾**：墙脸附近的零星假 FREE/假 WALL 斑点目前是净空场的隐性噪声源
   （一个斑点就打一个 1.2m 的洞），可做小连通域滤波/多帧确认，进一步收紧静态墙的误差预算。

每落地一项，PASS_CLEAR 就可以阶梯下探一档（0.6 → 0.45 → 0.3…），
每档跑四场景回归验证（bounce/collision 双指标，collision 必须保持 ~0）——
用数据决定能走到哪一档，而不是拍脑袋。**当前状态：未开工，仅设计。**
