────────────────────────────────────────────────────────────────
二、存在"部分幻觉"/夸大,共 6 处
────────────────────────────────────────────────────────────────

1. "不用任何世界真值"夸大了(README 〇/★节)。实际:
   - 默认运行定位用 d.qpos 真值位姿(--odom 1 才用里程计,且非默认);
   - DWA 直接拿移动障碍的真值速度向量(random_field.velocities,dwa.py);
   - 经验墙写入用真值确认(algo3_headless.py:1361,注释自认)。
   无特权成立的范围是感知/规划/终点发现,不含定位与障碍速度。

2. README 里程计声明与事实相反:README 说"(2%)漂移收敛到 0.1-0.5m"。
   实测 --odom 1(默认 2% 噪声)彻底失败——12 万步碰撞、跑出地图外
   (y=53.6)、未到达。0.5% 噪声才到达(32520 步,最终漂移 0.16m),
   但仍有 127 步碰撞,违反"碰撞=0"铁律。详细文档(08-09-fixes §3)
   其实诚实承认了 2% 失败、需要 scan-matching,是 README 没同步。

3. "地图保持精确边缘"打了折扣:感知层有墙厚先验(+0.1~0.2m)、
   障碍按 0.7m 膨胀盘"看到"(OBS_CLEAR,障碍在地图里比实际粗 0.4m)、
   移动障碍留残影。墙 precision 仅 65%。规划层零膨胀是真的,
   地图层"精确"是近似。

4. "二维码 10/10 全识别"不实:复现中固定×20 场只识别 5/10、
   混合场 9/10(不影响默认模式导航,但与表格声明不符)。

5. 覆盖率指标失真:四个场景 coverage 都 >104%
   (分母排除障碍格、分子含障碍残影)。

6. 旧账未清:docs/2026-08-10-gate-width.md 的"终版"表
   (移动×4:27054 步/bounce 0)是障碍随机化之前的数字,
   与现代码不符(README 已更新,gate-width 文档未更新);
   tests/test_lidar.py、test_integration.py 导入已删除的类,收集即报错。

另需理解的两个语义(文档有标注,但易误读):
- "到达终点" = 视觉确认到绿球约 3.5~4.5m 内,不是踩到球;
- collision=0 是算法禁行保证的——整个 MuJoCo 世界 contype=0,
  机器人是滑动胶囊,物理上根本没有接触这回事。

────────────────────────────────────────────────────────────────
四、上真实机器人还要加什么
────────────────────────────────────────────────────────────────

1. 定位传感器与算力(最关键):仿真默认用真值位姿,真狗没有。
   需要 IMU(宇树自带)+ 腿部里程计,且必须补激光/视觉 SLAM
   (scan-matching 或概率占据栅格)——odom 实验证明硬栅格+稀疏标牌
   修正撑不住 2% 漂移。

2. 激光雷达:前向 ≥180°、量程 30m 级单线(或多线取水平层),~10Hz。

3. 前视相机(桅杆 ~1m 高):用于目标识别与 ArUco/AprilTag 修正;
   若沿用现有到达判定,环境里要布设已知位姿的标牌并注册
   (环境基础设施)。

4. 机载计算:Jetson Orin/NUC 级(170 步/s 的决策+视觉+DWA,
   实时化要重做)。

5. 执行层:真实四足本体 + RL 步态控制器(README 已定方向),
   另需急停/安全触边——仿真的"碰撞=0"是算法禁令,真机没有这道保险。

6. 可选:深度相机(玻璃/激光盲区障碍)、目标物语义识别(替代"绿球")。

────────────────────────────────────────────────────────────────
总结
────────────────────────────────────────────────────────────────

文档的成绩单真实可复现、无捏造;但"完全无真值/里程计可用/地图精确/
二维码全识别"这几处是夸大或未同步,其中里程计模式(2%)实际是坏的。
算法对本迷宫高度特化,换房间首先要解决门宽阈值、地图尺寸/来源和
回环定位三件事。
